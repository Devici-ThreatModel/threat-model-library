## Vehicle Control & Safety Critical (CAN Bus & ECUs)

| Threat | Framework | Likelihood | Severity | Priority | Affects | Attacker goal / impact | Recommended mitigations |
|---|---|---|---|---|---|---|---|
| **Braking & Safety ECU Command Suppression / Safety System Disablement** | STRIDE: Denial of Service | Low | Critical | **Critical** | Braking & Safety ECU | Prevent brakes or airbags from deploying during an emergency. | Hardware-Enforced Safety Overrides and Fail-Safe Operating Modes<br>Secure Gateway Filtering With Safety-Critical Message Authentication |
| **ECU impersonation / spoofing** | STRIDE: Spoofing | Medium | Critical | **Critical** | CAN Bus | A compromised non-critical ECU (e.g., Radio) pretends to be the Safety ECU to send fake commands. | ECU Identity Verification With Message Authentication and Secure Gateways<br>Segmented Network Architecture With ECU Whitelisting and ID Filtering<br>Detect Duplicate or Out-of-Context ECU Identifiers at the Central Gateway With Alerting |
| **Gateway or bridge compromise** | STRIDE: Elevation of Privilege | Medium | Critical | **Critical** | Central Gateway ECU | The "Holy Grail" attack: Breaking the segmentation between Infotainment and CAN Bus. | Hardened Gateway ECUs With Domain Isolation and Message Authentication<br>Secure Gateway Firmware, Access Controls, and Continuous Monitoring |
| **Lateral movement to CAN or vehicle control networks** | STRIDE: Elevation of Privilege | Medium | Critical | **Critical** | Infotainment OS, Central Gateway ECU | Moving from a compromised Wifi/Bluetooth entry point into the safety network. | Secure Gateway Enforcement With Anomaly Detection and Access Controls<br>Strong Network Segmentation With Isolated Safety-Critical Domains |
| **ADAS Sensor Manipulation / Assistance System Degradation** | STRIDE: Tampering | Medium | Critical | **High** | Lane keeping, adaptive cruise control, and parking sensors | Cause the vehicle to ignore obstacles or brake unnecessarily (phantom braking). | Fail-Safe ADAS Modes With Redundant Perception Paths<br>Sensor Fusion Validation and Secure ADAS Message Filtering |
| **Bus flooding / Denial-of-service (DoS)** | STRIDE: Denial of Service | Medium | High | **High** | CAN Bus, Central Gateway ECU | Flood the CAN bus to freeze ECU communications; vehicle enters "limp mode" or shuts down. | Rate-Limiting and Priority Enforcement at Secure Gateways<br>Segmented CAN Networks With DoS-Resilient Isolation |
| **Diagnostic interface exploitation (OBD-II, UDS)** | STRIDE: Elevation of Privilege | High | High | **High** | OBD-II Port, Central Gateway ECU | Bypass authentication to inject CAN messages via physical port (Key cloning, theft). | Access-Controlled Diagnostic Modes With Strong Authentication<br>Gateway-Level Filtering and Segmentation of Diagnostic Traffic |
| **ECU firmware manipulation or reflashing** | STRIDE: Tampering | Low | Critical | **High** | CAN Bus, OBD-II Port | Permanently alter vehicle behavior, remove speed limiters, or disable safety features. | Cryptographically Signed Firmware and Secure Boot Enforcement<br>Hardened Update and Diagnostic Access Controls<br>Secure Boot Failure and Integrity Reporting to the Manufacturer Backend |
| **Engine & Powertrain ECU Overload / Destructive DoS** | STRIDE: Denial of Service | Low | Critical | **High** | Engine & powertrain ECU | Cause physical damage to the engine (overheating, over-revving) via repeated commands. | Engine Safety Limiters Enforced at Hardware and ECU Levels<br>Rate-Limited, Authenticated Control Traffic Through a Secure Gateway |
| **Exploiting insecure bootloaders** | STRIDE: Tampering | Low | Critical | **High** | CAN Bus, Hardware Security Module (HSM) | Bypass trust chain to load malicious OS or firmware on ECUs. | Locked-Down Bootloader Access and Controlled Update Paths<br>Verified Boot With Hardware-Backed Root of Trust |
| **Memory corruption or buffer overflow in ECU software** | CWE / STRIDE: Tampering | Medium | High | **High** | CAN Bus | Crash an ECU or execute arbitrary code via malformed packets. | Input Validation and Gateway-Level Sanitization of Network Traffic<br>Memory-Safe Parsing, Bounds Enforcement, and Hardened Firmware Builds |
| **Replay attacks on CAN traffic** | STRIDE: Spoofing | High | Medium | **High** | CAN Bus | Capture and re-send valid commands (e.g., "Unlock Door") to trigger actions without auth. | Message Freshness Enforcement With Counters, Nonces, or Timestamps<br>Secure Gateway Filtering With Context and Rate Validation |
| **Unauthorized CAN message injection** | STRIDE: Tampering | Low | Critical | **High** | CAN Bus, OBD-II Port | Send fabricated messages to control steering, acceleration, or braking. | Secure Gateways With Message Authentication and Signal Validation<br>Segmented CAN Networks With Strict ECU Access Controls<br>CAN Intrusion Detection on the Central Gateway With Alerts to the Manufacturer Backend |
| **Key or credential leakage from ECUs** | STRIDE: Info Disclosure | Low | High | **Medium** | CAN Bus, Hardware Security Module (HSM) | Extract cryptographic keys to decrypt firmware or spoof valid messages. | Hardware-Backed Secure Key Storage and Non-Extractable Secrets<br>Locked-Down Debug/Programming Interfaces With Secure Access Controls |

## Connectivity & Infotainment (Entry Points)

| Threat | Framework | Likelihood | Severity | Priority | Affects | Attacker goal / impact | Recommended mitigations |
|---|---|---|---|---|---|---|---|
| **Bluetooth exploitation** | STRIDE: Elevation of Privilege | High | Medium | **High** | Bluetooth Controller | Remote code execution or pairing without consent to access contacts or unlock the car. | Hardened Bluetooth Pairing and Authenticated Sessions<br>Restricted Bluetooth Attack Surface and Anomaly-Aware Handling |
| **Compromised mobile app integrations (Android Auto / CarPlay)** | STRIDE: Spoofing | High | Medium | **High** | Infotainment OS | Use a compromised phone to send malicious input to the head unit. | Controlled USB / Wireless Interfaces With Policy Enforcement and Threat Detection<br>Strict Isolation and Sandboxing Between Mobile and Infotainment Domains |
| **Security Misconfiguration (Web and Mobile)** | OWASP: Security Misconfig | High | High | **High** | Infotainment OS | Default passwords or open debug ports left on the Infotainment OS. | Disable Default Credentials and Debug Ports (ADB, UART, JTAG) on the Infotainment OS<br>Minimal Infotainment OS Image With Only Required Services Enabled<br>Regular, Secure, and Verified Software Update Pipelines |
| **Keyless entry relay and replay attacks** | STRIDE: Spoofing | High | Medium | **High** | Keyless Entry Receiver | Unlock and start the vehicle without the owner's key, to steal the vehicle or its contents. | Distance-Bounded Passive Entry With Ranging or Motion-Gated Fobs<br>Challenge-Response and Rolling Codes Between Fob and Keyless Entry Receiver<br>Cryptographic Immobilizer Check Between Body ECU and Engine ECU<br>Alert on Repeated Failed or Out-of-Range Keyless Authentication Attempts |
| **Client-Side Injection** | OWASP: Injection | High | Low | **Medium** | Infotainment OS | Execute malicious scripts in the Infotainment browser/UI. | Implement Parameterization<br>Validate User Input |
| **Malicious USB device injection** | STRIDE: Tampering | Medium | Medium | **Medium** | USB Controller | Fuzzing the USB stack to crash the Infotainment OS or gain shell access. | Restricted USB Functionality With Strict Parsing and Allowed Device Profiles<br>USB Port Access Controls and Execution Barriers for Untrusted Devices |
| **Voice-assistant command injection** | STRIDE: Tampering | Medium | Medium | **Medium** | Infotainment OS | Using hidden audio frequencies or recorded voice to trigger commands (e.g., "Open Garage"). | Privacy-Respecting Voice Processing and Restricted Data Exposure<br>User-Verified Actions and Robust Command Authentication |
| **Session Hijacking** | OWASP: Broken Access Control | Medium | Low | **Low** | Infotainment OS | Taking over an active user session (e.g., Spotify or Navigation) to steal data. | Encrypt all sensitive data in transit and at rest<br>Implement strong authentication with 2FA or MFA.<br>Secure Service Token Management |
| **Side-channel data leakage** | STRIDE: Info Disclosure | Low | High | **Low** | Infotainment OS, Hardware Security Module (HSM) | Analyzing power consumption or EM emissions to deduce crypto keys (very advanced). | Constant-Time Cryptography and EM/Power Shielding for the HSM and Key-Handling ECUs |

## Software Lifecycle, Backend & Privacy

| Threat | Framework | Likelihood | Severity | Priority | Affects | Attacker goal / impact | Recommended mitigations |
|---|---|---|---|---|---|---|---|
| **Broken Authentication** | OWASP: Identification Failures | High | High | **Critical** | Infotainment OS | Weak passwords allowing attackers to log into the vehicle mobile app/account. | Deploy anti-brute force protections<br>Implement strong authentication with 2FA or MFA.<br>Map all authentication flows<br>Secure credential recovery endpoints<br>Alert on Anomalous Sign-In Patterns and Lock Affected Owner Accounts |
| **Exploiting legacy or unsupported firmware** | OWASP: Vulnerable Components | High | High | **Critical** | Infotainment System | Attacking known vulnerabilities in old libraries (e.g., old Linux kernel in Infotainment). | Mandatory Firmware Lifecycle Management and Decommissioning<br>Secure Gateway Isolation and Hardening of Legacy Components<br>Fleet Firmware Inventory With Targeted Recall or Forced Update for End-of-Support Units |
| **Hijacked OTA (Over-the-Air) update mechanisms** | STRIDE: Tampering | Low | Critical | **Critical** | Infotainment OS, Hardware Security Module (HSM) | Pushing a malicious firmware update to the entire fleet of vehicles. | End-to-End Signed OTA Packages With Secure Boot Enforcement<br>Hardened OTA Delivery Infrastructure With Authenticated Update Channels<br>Automatic Rollback to Last-Known-Good Firmware With Staged Fleet Rollout |
| **Insecure Data Storage** | OWASP Mobile: Insecure Storage | High | High | **Critical** | Infotainment OS | Storing tokens or keys in plaintext on the Infotainment file system. | Encrypt all sensitive data in transit and at rest<br>Rotate Tokens and Keys Stored on the Infotainment Head Unit After Suspected Compromise |
| **Broken access control** | OWASP: Broken Access Control | Medium | High | **High** | Infotainment OS | User A accessing User B's vehicle telemetry or location data. | Deny Access by Default<br>Enforce record ownership in models<br>Implement Access Control Measures<br>Per-Vehicle Authorization on Telemetry and Location APIs |
| **Cryptographic failure** | OWASP: Crypto Failures | Low | Critical | **High** | Infotainment OS | Weak encryption enabling decryption of OTA updates or stored user data. | Classify data sensitivity<br>Encrypt all sensitive data in transit and at rest<br>Implement up-to-date encryption standards |
| **Data Disclosure** | LINDDUN: Identifiability | High | Medium | **High** | Bluetooth Controller, GPS | Leaking GPS history or PII (Personally Identifiable Information) to unauthorized parties. | Encrypt all sensitive data in transit and at rest<br>Implement Access Control Measures<br>Implement an anonymity system<br>Implement privacy-preserving authentication methods.<br>Implement privacy-preserving cryptographic protocols<br>Implement pseudonymity systems<br>Minimize and Expire Stored GPS and Trip History With Owner-Controlled Deletion |
| **Exploiting unpatched software vulnerabilities** | OWASP: Vulnerable Components | Medium | High | **High** | Infotainment OS | Zero-day attacks on the OS or 3rd party libraries. | Hardening of Infotainment OS and Isolation From Critical Networks<br>Regular, Secure, and Verified Software Update Pipelines |
| **Insecure Inter-Process Communication (IPC)** | STRIDE: Elevation of Privilege | Medium | High | **High** | Infotainment OS | malicious app on Infotainment talking to the Gateway service without permission. | Authenticated, Permission-Scoped IPC Between Infotainment Services and the Gateway Service |
| **Insufficient Transport Layer Protection** | OWASP: Crypto Failures | Medium | High | **High** | Infotainment OS | Sending telemetry or commands over HTTP instead of HTTPS (Man-in-the-Middle). | Encrypt all data in transit using secure protocols. |
| **Vulnerable and Outdated Components** | OWASP: Vulnerable Components | High | High | **High** | Infotainment OS | Using libraries with known CVEs (Common Vulnerabilities and Exposures). | Conduct Software Composition Analysis<br>Eliminate unused dependencies<br>Source trusted libraries and packages |
| **Weak Server-Side Controls** | OWASP API: Broken Object Level Auth | Medium | Critical | **High** | Infotainment OS | Backend API allowing unverified commands to be sent to the vehicle. | Implement Access Control Measures<br>Use Trusted Frameworks<br>Authorize Each Remote Command Against Owner, Vehicle and Command Type at the Manufacturer Backend |
| **HSM compromise or misuse of key operations** | STRIDE: Elevation of Privilege | Low | Critical | **High** | Hardware Security Module (HSM) | Defeat the hardware root of trust so forged firmware, updates or messages are accepted as genuine. | Authenticated, Rate-Limited HSM Key Operations Bound to Approved Callers<br>HSM Fault-Injection Resistance and Disabled Debug Interfaces in Production<br>HSM Key-Usage Audit Log Reported to the Vehicle Manufacturer Backend |
| **Insecure Communication with Third-Party Services** | OWASP API: Unsafe Consumption | High | Low | **Medium** | Infotainment OS | Intercepting data sent between the car and music/weather services. | Encrypt all data in transit using secure protocols.<br>Certificate Pinning and Mutual TLS for Navigation, Media and Weather Service Connections |
| **Malicious Code and Malware** | STRIDE: Tampering | Medium | Medium | **Medium** | Infotainment OS | Ransomware locking the infotainment screen until payment is made. | Application Allow-Listing and Code Signing Enforcement on the Infotainment OS<br>Factory Reset and Recovery Partition for the Infotainment OS |
| **Reverse Engineering** | STRIDE: Info Disclosure | High | Low | **Medium** | Infotainment OS | Analyzing app binaries to find API keys or logic flaws. | Implement Code Obfuscation<br>Keep API Keys and Certificates Out of Binaries by Storing Them in the HSM |
